A claim, and the thing that checks it

freshcart-backend allocates invoice numbers under contention. The claim is that the allocation is unique and gap-free, not a read-then-write that two callers can both win. The repository proves it: twenty-five allocators fire in parallel against a real MySQL instance in a container, and the test asserts the awarded set is exactly one to twenty-five. Below is that race.

A picture of a race is not evidence. The evidence is the test in the repository, which fails if the invariant ever stops holding.

Open source

20 pull requests merged into projects maintained by other people. One of those is in a major project; the rest are in smaller ones. That distinction matters, so it is stated here rather than left to be discovered.

BerriAI/litellm

Stale spend counters kept returning HTTP 429 after a budget window had rolled over.

A production LLM gateway with more than fifty thousand stars. Resetting an end-user budget cleared the spend in Postgres but left the cached counter alive on other workers and replicas, so requests kept being rejected against a budget that had already reset. The fix invalidates the counter across the cache tier, and ships with dedicated regression tests and a documented two-replica reproduction.

Pull requests

All merged pull requests

  • BerriAI/litellmAn end-user budget reset zeroed the spend in Postgres but not the cached spend counter, so multi-worker and multi-replica proxy deployments kept returning HTTP 429 'Budget has been exceeded' after the budget window had already rolled over, until the caches expired on their own; the fix zeroes spend:end_user:<id> in both in-memory and Redis caches, evicts the cached end-user object on every worker rather than just the one running the reset job, extends rollover carry to default end-user budgets as well as explicit ones, and floors a stale cached spend against LiteLLM_EndUserTable.spend with a 5-second in-process cache, across 283 added lines with three dedicated regression-test files (+283/-30, 6 files).
  • apmantza/pi-lensOn a cold first edit the auxiliary LSP servers (opengrep, ast-grep) were only spawned after the primary server's resync had been awaited, so the edit hook paid primary spawn plus auxiliary spawn strictly in sequence (~7s observed); the fix kicks off getAuxiliaryClientsForFile unawaited at resync time under the turn's ambient abort signal so the two spawns overlap and the later with-auxiliary request either finds them warm or joins the same in-flight acquisition, adds optional maxWaitMs/signal/hook bounding per server, and records a new auxiliary_readiness latency phase excluded from stall attribution (+349/-5, 9 files, including a 227-line new concurrency test).
  • schubydoo/clausterensure_gitignored only checked for an exact line match when writing local-scope files such as .claude/settings.local.json, so when an ancestor rule like /.claude, .claude/ or .claude already ignored the whole directory it still appended duplicate entries and left unexpected working-tree modifications on main; the fix adds _is_gitignored_by_existing_rules to match root-anchored directory rules, unanchored directory rules, exact lines with or without a leading slash, and basename wildcards such as *.bak, turning already-covered paths into a clean no-op (+261/-9, 3 files, 155 lines of it tests).
  • MihaelaAghirculesei/n8n-probeThe CJS fixture node requires n8n-workflow while the ESM test suites import the ESM build, producing two copies of the same classes and breaking instanceof checks; the alias pinning resolution to CJS had been copy-pasted into six separate package vitest configs, so the fix extracts a root vitest.config.base.ts holding that alias once and has every package extend it through mergeConfig while keeping its own coverage and environment settings (+109/-84 across 7 files, a net reduction in duplicated config).
  • calibrain/shelfmarkDownloading an audiobook with 250+ chaptered tracks produced two split book folders, because indexer XML capped the release file list at roughly 110 entries, match_plan_to_files matched only those to the planned book, and the remaining 140+ files fell through to heuristic grouping which parsed the folder name and invented a second book; the fix checks unmatched files before that fallback and appends chaptered audio (.flac, .mp3, .aac) to an existing group when it shares the directory or the plan was single-book, while leaving standalone .m4b/.epub files and separate subfolders on the old path (+97/-2, 2 files, 76 lines of tests covering truncated lists, CD1/CD2 multi-disc, and multi-book packs).
  • wemake-services/django-modern-restNot a bug fix but an API-naming correction: the library's string-serialization helper was named json_dump, which in stdlib convention means writing to a file object rather than returning a string, so it was renamed to json_dumps in dmr.internal.json and dmr.openapi.dump with call sites in OpenAPIJsonView and the test client updated, a deprecated json_dump = json_dumps alias retained for backwards compatibility, tests added, and the breaking change recorded in CHANGELOG under 0.15.0 (+13/-9, 5 files).
  • atretyak1985/swarmerySix Claude Code skills across two plugin packs had frontmatter descriptions that said what the skill covers but never what it excludes, so overlapping skills competed for the same prompts; the fix adds an explicit negative-boundary clause to each description naming the sibling skill that should handle the excluded case (for example, routing symbol searches away from graphify to code-search, and tool-schema questions away from auditing-agent-architecture to designing-tools-and-mcp), and bumps both packs 1.1.0 to 1.1.1 (+8/-8 across 8 files - one line changed per file).
  • theagentplane/tokenopsA four-line docstring correction: the policies package pointed readers at a tokenops-lld/policies/ directory that does not exist in the repository (now docs/policies/) and gave no reason why trajectory_hint is absent from the exported policy templates, which the change explains - it requires a Store and is configured in control/config.py instead (+4/-1, 1 file).
  • felladrin/MiniSearchA one-line change: npm run lint emitted 'The configuration schema version does not match the CLI version 2.5.11, Expected: 2.5.11, Found: 2.5.8' on every run, so the $schema URL in biome.json was bumped from 2.5.8 to 2.5.11 via biome migrate to clear the warning (+1/-1, 1 file).
